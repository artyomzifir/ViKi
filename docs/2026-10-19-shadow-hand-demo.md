# Shadow Hand: объектная демонстрация G10_2

## Вход и границы эксперимента

- Эпизод: `data/datasets/hocap_demo_object_v4/g10_object2_190`, первые 190 кадров HO-Cap `subject_1-20231025_170105`, 30 Гц.
- Источник: конечный `hand_fit_*` из `cln.npz`, профиль `hocap-stable-fused-hand-v4`, overlay `articulated-landmarks-v1:optimized`; quality gate принят.
- Сравнение конечной человеческой кисти с GT: MPJPE **10.7802 мм**, медиана **9.9320 мм**, p95 **20.3777 мм**, 3990/3990 суставов. Это ошибка человеческой реконструкции, не точность робота.
- Робот: UR10 + официальная правая Shadow Hand; 6 суставов руки и 22 сустава пальцев. Два собственных запястных сустава Shadow исключены при сборке, ладонь закреплена на `tool0` адаптером 55 мм. Это экспериментальная виртуальная установка.
- Объект №2; используются записанные позы объектов и официальный меш, выровненный в систему объектного трека. Объектная модель основана на oracle instance masks и построена по полному исходному ролику из 831 кадра: геометрия содержит информацию из будущих кадров. Это демонстрация, не независимый online benchmark.
- Облако Viewer восстановлено из двух настоящих RGB-D камер. Поскольку отдельной depth-калибровки нет, построитель использовал pinhole fallback с предположением совмещения depth/color.

## Исправленная ошибка

Прямое копирование человеческих углов в Shadow создавало пересечения пальцев. Максимально наблюдавшееся проникновение указательного и среднего пальцев — 11.709 мм. Пальцы были пассивными входами arm IK: движение UR10 не могло исправить это противоречие. Поэтому прежнее `primal infeasible` не доказывало невозможность антропоморфного ретаргета.

Новый перенос получает ориентиры через FK **конечной** fitted модели. Направления фаланг переносятся на длины Shadow, затем подбираются 22 сустава с URDF-лимитами, временной регуляризацией и штрафом за сближение выборок фаланг. Штраф — приближённый; отдельная проверка итоговой траектории использует vendor collision geometry через Pinocchio/Pink. Общий self-collision clearance для этого эксперимента — 1 мм; прежняя попытка использовала 5 мм.

Положение/ориентация ладони зависят от трека объекта: контакт 23–150, object-relative carry 42–125 включительно. Вне carry используются конечные fitted позы с переходами. Это условный геометрический план; жёсткие препятствия от всех объектных мешей пока не включены в IK.

## Визуализация и физика

Viewer имеет явный выбор `Shadow Hand · object plan`. Отсутствие этого артефакта не подменяется `plan.h5` с Robotiq. Экспорт содержит SHA-256 исходного Shadow-плана; сервер отклоняет устаревший экспорт. Меши объектов и точки rigid core включаются отдельно.

Физический replay читает тот же `shadow_object_plan.npz`: 28 сохранённых команд, реальные URDF-меши и четыре объекта. Запрещены принудительное задание поз объектов и weld. Масса каждого объекта 80 г, коэффициент трения 1.2, gravity compensation робота, позиционные приводы. Контакты объектов вычисляются по выпуклым оболочкам официальных мешей. Это явно заданные параметры симуляции, не измеренные физические свойства сцены.

## Результат

Итоговый объектный план рассчитан, экспортирован и физически проигран в **native MuJoCo GUI**. Это UR10 + Shadow Hand, а не Robotiq. Viewer и MuJoCo читают один сохранённый план.

Использован покадровый IK с проверкой всей полученной последовательности (`framewise_ik_whole_trajectory_validated`), не сходимость batch-оптимизатора. Проверены лимиты суставов, скорости, пол и self-collision. Минимальный зазор до пола 2.847 мм; запас сверх self-collision clearance 1 мм — 0.114 мм. Время растянуто с 6.299937 до 6.603945 с по ограничениям скоростей всех 28 суставов; минимальный запас скорости после retiming — 0.03922 рад/с. Между сохранёнными командами replay выполняет линейную интерполяцию, а состояние снимает у соответствующего целевого кадра. Длительности сегментов округляются до шага физики 0.5 мс.

При carry пальцы удерживают объектно обусловленную конфигурацию. Цели пальцев дополнительно сближены на **5 мм** к продольной оси объекта. Усиление пальцев `kp=16`, `kv=0.15`, пределы усилий взяты из URDF; для руки `kp=1800`, `kv=120`. Усиление не означает снятия ограничений усилия.

| Измерение | Среднее, мм | Медиана, мм | p95, мм |
|---|---:|---:|---:|
| Конечный human hand-fit против HO-Cap GT, MPJPE | 10.780 | 9.932 | 20.378 |
| Геометрический IK: достигнутый wrist против целевого | 2.707 | <0.001 | 15.542 |
| MuJoCo: положение объекта против записанного объектного трека | 27.835 | 27.916 | 63.576 |

Это три разные метрики. Первая оценивает реконструкцию человека, вторая — выполнение IK-целей, третья — отклонение свободного физического объекта от референсного трека. Третья не является MPJPE и не доказывает точность на железе.

- Максимальный подъём объекта: **243.510 мм**.
- Конечное отклонение объекта: **27.865 мм**.
- Одновременный контакт большого и остальных пальцев: 67/190 кадров; в carry — 69.05% кадров.
- p95 ошибки объекта только в carry: **95.147 мм**.
- Контактов робота со столом: **0 шагов**.
- Медиана абсолютной ошибки приводов: рука 0.010283 рад, пальцы 0.000937 рад.
- `gui_enabled=true`, `assistance=none`, **`success=false`**.

**Устойчивое удержание не достигнуто:** предмет поднимается, затем проскальзывает. Gate требует подъём >20 мм, >10 кадров встречного контакта, конечную ошибку <20 мм, встречный контакт на ≥80% carry, carry p95 <30 мм и отсутствие контакта со столом. Часть условий не выполнена. GIF показывает демонстрационный прогресс, а не успешную физическую валидацию захвата.

### Подбор усиления

| GUI-вариант | Среднее / медиана ошибки объекта, мм | Конечная ошибка, мм | Подъём, мм |
|---|---:|---:|---:|
| 4 мм, kp=12 | 50.183 / 23.995 | 95.663 | 244.068 |
| 6 мм, kp=20 | 91.816 / 123.442 | 123.654 | 242.616 |
| **5 мм, kp=16 — итог** | **27.835 / 27.916** | **27.865** | **243.510** |

Более сильное сжатие не улучшало все показатели: вариант 6 мм оказался хуже. Итоговый вариант снизил среднюю и конечную ошибку относительно 4 мм, но медиана стала немного хуже. Предыдущие неудачные прогоны, включая нестабильный high-gain и ступенчатые команды до исправления интерполяции, сохранены в `data/experiments/hocap-rl/shadow_initial/`.

## Воспроизведение

```bash
docker compose run --rm terminal python3 /app/experiments/prepare_shadow_urdf.py
docker compose run --rm terminal python3 /app/experiments/hocap_shadow_object_attempt.py --solver framewise --grasp hold --closure-m .005
docker compose run --rm terminal python3 /app/experiments/shadow_viewer_export.py
# Из desktop-сессии с действующими DISPLAY и XAUTHORITY:
./experiments/run_shadow_viewer.sh
```

Требуются локальные HO-Cap-данные, официальные модели, собранный image `viki-experiments` и доступ к X-сессии/GPU. Исходные данные/URDF/планы не коммитятся. Shadow пока подключён как явный экспериментальный артефакт, а не как законченная production-интеграция реестра роботов.

Полный Docker pytest: **525 passed, 10 skipped** (30.94 с). `node --check` для изменённых `viewer.js`/`scene3d.js`, Python compile и `git diff --check` пройдены. Физический сценарий дополнительно проверен реальным GUI-прогоном.
