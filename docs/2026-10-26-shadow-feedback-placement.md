# Shadow offline feedback placement and force-maintenance pilots (2026-10-26)

These are **opt-in experiments on one frozen 190-frame HO-Cap G10_2 scene**, not production retarget changes. The input is the earlier MF +0.10/RF +0.08 three-digit grasp. Both pilots copy every original command and timestamp through frame 110 bit for bit, then observe the *true MuJoCo object pose, actual arm/palm pose and measured digit forces during offline command generation*. They save a longer, named, timestamped **open-loop** command; a fresh replay uses only that file, without feedback, object forcing, welds, changed physics, gains, friction or collision filters. Simulator state is an oracle unavailable from the current perception pipeline. The original 190-frame task phases and strict gates remain as the source control; applying their frame indices to a 226–229-frame trajectory would be misleading. We report new extended placement, controlled-touchdown and full-scene diagnostics separately. The unchanged source pickup p95 over frames 42–59 remains 59.47 mm.

## Arm/object-pose feedback: upright landing after grip loss

The arm controller begins at frame 110, where the source object is airborne at z=134.3 mm, tilt=12.4° and descending at 0.275 m/s, with thumb/index/middle force about 3.8/2.4/1.6 N. At each subsequent frame, it recomputes the *current* object-to-palm transform from actual simulation state, takes a bounded object-centered position/rotation step toward the tracked final XY/rotation, and solves only six arm joints by FK/IK. Palm position and rotation steps are acceleration-limited from the source frame109→110 motion to avoid an instantaneous stop. The target center height uses the official object mesh and unchanged table. The controller first tries to align upright above support, then descend. The original frame-110 finger command holds until at least nine consecutive frames have ≥95% positive-force table support, object tilt <8° and speed <0.03 m/s. Only then does the original finger-opening path from source frames125–151 run, followed by 50 mm retreat and 15 observation frames. The source finger path retains its *actual irregular segment durations*; imposing a uniform 33.333 ms segment caused a documented velocity rejection at source frame148 in the first launch. That first launch is preserved as [arm_initial ledger](../paper/results/shadow_feedback_placement_2026_10_26/arm_initial_ledger.jsonl); the corrected run changed timing, not physical parameters or gains.

Two arm settings were fixed: 2 mm/1° and 3 mm/1.5° maximum object step, with respectively 1/1.5 mm and 0.5/0.75° palm-command acceleration limits per frame. Each generated command must pass the unchanged URDF joint limits and actual segment velocities, IK ≤1.5 mm/1°, and candidate-specific passive-finger floor/screened self-clearance before the next physics step. The nominal 2-second settle gate asks for final XY<30 mm, Z<20 mm, reference rotation<15°, upright tilt<15°, last-second table support≥95%, no hand/robot-table contact, speed<0.03 m/s and peak pose drift<5 mm/5°. Both commands passed this **terminal upright-settle diagnostic**; the selected 226-frame firm command had XY8.39 mm, Z1.52 mm, reference rotation13.31°, upright tilt1.77°, 100% support and no hand force in the last second. Its [report](../paper/results/shadow_feedback_placement_2026_10_26/arm_report.json), [ledger](../paper/results/shadow_feedback_placement_2026_10_26/arm_ledger.jsonl), [generation trace](../paper/results/shadow_feedback_placement_2026_10_26/arm_candidate_1_generation.json), and [saved command](../paper/results/shadow_feedback_placement_2026_10_26/arm_final_commands.npz) retain the measurements. Internal no-oracle replay reproduced every generated object position and rotation bit for bit, plus all 12 saved physical trajectory arrays.

A review of physics-step contacts exposed a false positive for **controlled** placement. Before first table contact, the selected command has thumb plus two other digits above 0.05 N in only 60.2% of steps, with a 0.464 s force gap. The object first hits the table at frame145 at **0.724 m/s** and then happens to settle upright; the gentler command first touches at frame152 at 0.545 m/s, with 64.1% triad force and a 0.458 s gap. Consequently neither command maintains a grasp through touchdown. This was a post-run validity correction, not a ranking or threshold retune: the original optimistic `accepted=true` report and manifest are preserved as [pre-review evidence](../paper/results/shadow_feedback_placement_2026_10_26/arm_report_pre_review.json), while the current [corrected report](../paper/results/shadow_feedback_placement_2026_10_26/arm_report.json) states `accepted=false`. The independently replayed [physics-step audit](../paper/results/shadow_feedback_placement_2026_10_26/arm_audit_replay_report.json) records the loss and impact. A separate controlled-touchdown diagnostic requires ≥90% pre-support triad-force steps, no gap >0.05 s and first support speed <0.1 m/s, plus no forbidden robot contacts; both fail. The stricter full-scene 5 mm bystander-drift gate also fails: peak displacement is 20.36/20.78 mm, with zero robot–other-object contact. The unchanged simulator reports −7.62 mm minimum target contact separation, limiting physical fidelity.

## Bounded TH/FF/MF contact maintenance

After the arm-only false positive, **exactly two** TH/FF/MF controller settings were declared in [contact protocol](../paper/results/shadow_feedback_placement_2026_10_26/contact_protocol.json). Both reuse the firm arm law. At frame110 the true simulated forces are thumb/index/middle 3.754/2.401/1.412 N; targets are 80% of each. Per frame, an integral closure residual increases when a digit’s **frame-mean positive normal force** falls below its target; outcome audits use physics-step forces. It drives THJ4 and FF/MF J1/J2/J3 with weights 1/0.7/0.35. Variant A gains 0.003 rad/(N·frame) and caps thumb/index/middle at +0.06/+0.12/+0.12 rad; B gains 0.006 and caps +0.08/+0.18/+0.12 rad. These are declared *control* saturation bounds, not clipping of a URDF-invalid trajectory; each realized command still undergoes joint, velocity, IK, floor and self checks. Closure freezes only after **three consecutive supported frames**, not one transient contact. On qualified release it fades smoothly over the source finger-opening path, using exact source segment durations.

The [contact ledger](../paper/results/shadow_feedback_placement_2026_10_26/contact_ledger.jsonl) and both [generation traces](../paper/results/shadow_feedback_placement_2026_10_26/) show that neither setting retains controlled touchdown. Variant A reaches thumb residual +0.06 rad, index +0.118 and middle +0.014; pre-support triad force rises to **64.4%** and its longest gap falls to 0.287 s, but first table contact at frame147 is still **0.694 m/s**. It later rests upright (settled XY14.47 mm, reference rotation5.59°, tilt1.77°), so terminal pose alone again passes while the controlled-touchdown gate fails. Its support begins frame147, closure freezes after sustained support at151, conditional opening starts162, and the [229-frame command](../paper/results/shadow_feedback_placement_2026_10_26/contact_final_commands.npz) replays exactly from a fresh scene. Variant B reaches 71.1% pre-support triad force but has a 0.335 s gap and first support at frame146. It never meets the align/release condition, then fails the unchanged IK tolerance at frame248 (5.89 mm position error); no full release command was exported for B. The full-scene bystander gate still fails for A (20.62 mm peak), with zero robot–other-object/table contact, zero actuator effort saturation, and +0.0193 rad/s sampled actual-joint velocity margin. The [independent saved-command audit](../paper/results/shadow_feedback_placement_2026_10_26/contact_replay_replay_report.json) carries those numbers.

The specific result is that bounded force-based flexion narrows, but does not close, the loss-of-contact interval in this grasp geometry. An upright final pose came from an uncontrolled impact in both pilots, so **no command is accepted as a repaired interaction**. The source grasp itself failed a separate two-second static hold, and the mesh/contact-depth and intrinsic bystander drift limit generalization from this one simulated scene. The added controlled-touchdown gate is clearly post-review for the arm-only run, then fixed before both contact-force variants; search ranking and raw outcomes were preserved. No further settings were tried.


The runner and its [bounded feedback controls](../experiments/shadow_feedback_placement_controls.py) are experiment-only. [Focused regression tests](../tests/unit_tests/experiments/test_shadow_feedback_placement_controls.py) cover object-centered SE(3) motion, smooth braking, force residuals, an upright-but-dropped failure, and extended command provenance/timing. ## Parent review and servo-deflection probes

A second runner, [hocap_shadow_export_review.py](../experiments/hocap_shadow_export_review.py), loads the original replay runner's scene XML and saved commands directly, without importing the placement generator or controller helpers. The original XML SHA-256 is `03d4cac1e9b2eaf33665f27418b83b0f8e3d2a82df17891114314b43a8d5a496`. The [model and trajectory comparison](../paper/results/shadow_feedback_placement_2026_10_26/parent_arm_array_comparison.json) checks unchanged masses/inertias, gravcomp, friction/contact parameters, collision filters, servo settings, limits, timestep and integrator; selected arm-feedback object trajectories and settle trajectories reproduce bit for bit. [Arm review](../paper/results/shadow_feedback_placement_2026_10_26/parent_arm_review.json) confirms the 0.724m/s touchdown and 0.464s force gap. [Contact-feedback review](../paper/results/shadow_feedback_placement_2026_10_26/parent_contact_review.json) independently confirms XY14.47mm, tilt1.77°, 0.694m/s touchdown, 64.4% pre-support triad and 0.287s gap. These remain rejected controlled-placement outcomes.

A follow-up code review noticed that converting the desired object step to an absolute pose of the **actual** palm discards command-versus-actual servo deflection. Two separately recorded [preload probes](../experiments/hocap_shadow_preload_placement.py) tested this, without changing physics, source prefix, finger closure or feasibility constraints:

* Incremental: apply the measured world SE(3) correction to the preceding commanded palm, preserving its current displacement from the actual palm. It keeps positive thumb/index/middle contacts through the generated frames, but commands progressively lower while the object remains around104mm high. Frame123 is rejected with a **−5.680mm floor margin**, so no complete command is accepted.
* Fixed: preserve the actual-to-command transform measured at frame110, avoiding integration of that displacement. It also retains the three contacts through first table support at122, but continues moving down while still in the align phase. Floor margin becomes **−1.513mm at125** and stops the run. This offset includes dynamic tracking lag from the initially descending trajectory; treating it as a static grasp preload is insufficient. First support alone is not evidence of a valid slow touchdown or completed release.

Protocols, partial traces and failure ledgers are preserved with `preload_incremental_` and `preload_fixed_` prefixes in the results directory. Neither floor rejection is bypassed, neither partial command is offered as a successful fix, and no gain sweep was performed. The practical next control question is how to separate grasp preload from dynamic servo lag and enforce a supported release without driving the closed hand through the table.
