# Shadow object-pose-aware placement pilot (2026-10-26)

This opt-in offline pilot tries to place HO-Cap G10_2 with the previously saved three-digit Shadow grasp. It changes only the six arm position commands after frame 100 in the selected command; the original finger commands, 190 timestamps, unforced four-object scene, mass, friction, gains, effort limits, collision filters and meshes remain unchanged. The new command is **diagnostic only**: no candidate places the object upright, none passes the unchanged target or full-scene task gate, and the two-second stability check fails. The recorded object track is a reference trajectory, not an independent success label; an independent audit found tracked-versus-aligned-GT object pose differences of median 3.78 mm/12.17° and maximum 9.02 mm/26.87° for this source (see the source-finger audit results when published).

The input is the earlier [multifinger follow-up](2026-10-25-shadow-multifinger-polisher.md) MF +0.10/RF +0.08 command because its thumb, index and middle fingers jointly retain positive force throughout carry, unlike the earlier pinch. It still fails a frozen two-second airborne grasp hold: 13.4 mm peak palm-relative slip, 17.2 mm fall and 23.6° rotation. We therefore treat placement improvement as a hypothesis on this one imperfect grasp, not as established grasp stability.

## Geometry and frozen tests

The initial eight-point family used the **actual simulated** object pose and actual palm FK at frame 90 in an unforced input rollout to measure a fixed object-to-palm SE(3) transform. This is a simulator-state oracle for *offline* command generation; a production robot would need perception. The source commanded palm poses plus that fixed transform predict nominal object poses. The target uses the tracked final object XY and rotation; center height comes from the lowest vertex of the official object_2 mesh after target rotation on the original table top, rather than treating the object origin as its bottom. The table top is z=−0.000933 m, mesh local minimum z=−0.075031 m, and the supported center is z=0.073867 m. The frame-90 measured object-to-palm translation is [0.09765, −0.09844, 0.00027] m in object coordinates; rotating the object therefore shifts the commanded palm position around the **object center**.

The fixed family crosses correction start frame {90,100}, endpoint orientation gain {0.75,1.0}, and clearance above mesh support {0,5} mm: eight commands total. The correction is smooth and complete by frame 125; the corrected palm holds to frame 151 while the original finger commands release, then rises 50 mm by frame 175. All 190 frames remain. Arm FK/IK reconstructs the palm command, with max accepted residual 1.5 mm/1°. The original URDF command position/actual-timestamp segment-velocity limits, candidate-specific passive-finger floor screen and screened self-pair clearance run before physics. This kinematic screen omits exhaustive collision against the other objects; the unchanged MuJoCo replay measures those contacts. No pose or control vector is clipped to pass a gate.

The [fixed protocol](../paper/results/shadow_object_pose_placement_2026_10_26/fixed_protocol.json) and [feasibility ledger](../paper/results/shadow_object_pose_placement_2026_10_26/fixed_feasibility.jsonl) show **0/8 feasible**: all met IK and command limits, but passive fingers crossed the unchanged floor screen near frames 120–125 (first margins −0.07 to −2.63 mm). We did not simulate these rejected commands or loosen the floor threshold. Their source control and scene are saved with the ledger.

After that rejection, a separately approved, explicitly **exploratory** eight-point clearance follow-up kept the same start and orientation axes but used 10/15 mm clearance. This tests whether an above-table release can be constructed without finger-floor penetration; it was not part of the original frozen family. [Protocol](../paper/results/shadow_object_pose_placement_2026_10_26/clearance_protocol.json), [feasibility](../paper/results/shadow_object_pose_placement_2026_10_26/clearance_feasibility.jsonl), and [rollout ledger](../paper/results/shadow_object_pose_placement_2026_10_26/clearance_rollout_ledger.jsonl) retain all eight settings, two rejections and six simulated outcomes. Ranking was declared as placement diagnostic pass first, then release/support/table/settling failure penalties and continuous final XY/Z/orientation/tilt error. Neither original task gate was relaxed.

The extra placement diagnostic holds the **last saved command for two seconds after frame 189** in the same unforced physics model. To pass, the final center must be within 30 mm XY and 20 mm Z of the recorded final pose, orientation within 15° of that reference and upright tilt below 15°; over the last second, positive-force table support must occupy at least 95% of steps, hand and robot-table contacts must be absent, speed <0.03 m/s, and peak position/rotation drift <5 mm/5°. The original 190-frame target and full-scene gates are reported separately. Pickup error over frames 42–59 is also separate because this placement-only edit cannot fix delayed acquisition.

## Result and failure analysis

Six exploratory commands passed kinematic screening; **0/6 passed upright placement**, the unchanged target gate or the full-scene gate. The selected diagnostic command is start=100, orientation gain=0.75, clearance=15 mm. Its maximum FK/IK position and orientation residuals are 0.731 mm/0.044°; minimum saved segment-velocity margin is 0.0136 rad/s, sampled actual-joint velocity margin 0.0223 rad/s, and screened floor/self margins are +9.37/+0.30 mm. These sampled/kinematic checks do not prove continuous-time hardware safety.

| Metric | Unmodified three-digit input | Selected placement command |
|---|---:|---:|
| Carry object position p95 vs track | 51.33 mm | 51.33 mm |
| Pickup frames 42–59 p95 | 59.47 mm | 59.47 mm |
| Final frame-189 object position error | 100.58 mm | 82.50 mm |
| Two-second settled XY error | 75.47 mm | 47.85 mm |
| Two-second settled Z error | 67.67 mm | 67.33 mm |
| Two-second settled reference rotation error / upright tilt | 92.41° / 95.42° | 93.80° / 95.28° |
| Last-second table support / hand force / robot-table force | 100% / 0 / 0 | 100% / 0 / 0 |
| Original target / full-scene / new upright placement | fail / fail / fail | fail / fail / fail |

Thus the selected command reduces horizontal miss, yet the object **rests on its side** about 67 mm below the intended upright center. The old target gate also fails the 51.33 mm carry p95 and final error thresholds; the full-scene gate still observes about 17.3 mm peak movement of another object, a known stationary-scene drift confound. The two-second settle is physically quiet (selected last-second max speed 0.0058 m/s, position drift 0.54 mm, rotation drift 0.23°), but quietness alone does not imply upright placement. The selected three-digit carry positive-force fraction falls to 96.9% near touchdown. Source finger commands and the frame-60 grasp hold are unchanged; static grasp still fails.

The saved [frame/physics-step diagnosis](../paper/results/shadow_object_pose_placement_2026_10_26/selected_diagnosis.json) explains the toppling. At frame 120 the object is 18.2° tilted; the index finger begins losing positive force at frame 123 and has none at frames 124–126. First target-table contact is at frame 125, full support by 126; actual center z=71.6 mm and tilt=24.7° at 125. Although palm IK tracks its desired pose closely, the *actual* object is then 19.9 mm and 18.3° away from the pose predicted by the fixed frame-90 object-to-palm transform. Thumb/middle contact survives briefly; all sustained hand force is gone by about frame 137. The object remains supported but tilted (~21–24°) through frame 140, then rotates rapidly (>180°/s by frame 142), reaches 42° tilt at 145 and ~95° after settling. This is consistent with grasp-relative drift leading to off-axis touchdown and unsupported tipping. The 15 mm nominal clearance does not yield a 15 mm actual gap at touchdown because the fixed grasp transform has already become inaccurate. Late hand pushing is not the main observed cause after frame 137, though contact impulses at touchdown and the simulator's mesh penetration limit inference. This causal account is an interpretation of one simulated trajectory, not a measured human hand force.

## Evidence and reproduction

The durable [result directory](../paper/results/shadow_object_pose_placement_2026_10_26/) includes both protocols and raw ledgers, every feasible follow-up command and physical trace, selected [open-loop command](../paper/results/shadow_object_pose_placement_2026_10_26/clearance_final_commands.npz), [FK/IK targets and realized poses](../paper/results/shadow_object_pose_placement_2026_10_26/clearance_candidate_5_ik.npz), [object/digit/force trajectory](../paper/results/shadow_object_pose_placement_2026_10_26/clearance_trajectory.npz), [two-second physics-step settle trace](../paper/results/shadow_object_pose_placement_2026_10_26/clearance_settle_trace.npz), and selected [report](../paper/results/shadow_object_pose_placement_2026_10_26/clearance_report.json). The command carries ordered names, exact timestamps, source plan/track/URDF/mesh/input hashes and its setting. Replay reconstructs it from those sources before physics. Its saved 190-frame metrics and two-second settle metrics matched exactly; all ten shared physical trajectory arrays and seven settle arrays were bitwise equal in [independent exported-command replay](../paper/results/shadow_object_pose_placement_2026_10_26/replay_replay_report.json). This is internal replay validation; a separate original-runner comparison is pending.

On this configured host, run the fixed and exploratory families in **fresh** output directories (the runner refuses an existing manifest/ledger):

```bash
docker compose -f docker-compose.experiments.yml run --rm sim experiments/hocap_shadow_object_pose_placement.py --output /app/rl-output/shadow_object_pose_placement_20261026
docker compose -f docker-compose.experiments.yml run --rm sim experiments/hocap_shadow_object_pose_placement.py --family exploratory_clearance8 --output /app/rl-output/shadow_object_pose_placement_clearance_20261026
docker compose -f docker-compose.experiments.yml run --rm sim experiments/hocap_shadow_object_pose_placement.py --family exploratory_clearance8 --replay /app/rl-output/shadow_object_pose_placement_clearance_20261026/final_commands.npz --output /app/rl-output/shadow_object_pose_placement_clearance_replay_20261026
```

The ignored local episode, official meshes, URDF and preceding multifinger command are required. The original first family took 21.3 s and the exploratory follow-up 81.4 s on this host. The code is experiment-only: [runner](../experiments/hocap_shadow_object_pose_placement.py), [rigid-pose controls](../experiments/shadow_object_pose_placement_controls.py), [geometry probe](../experiments/hocap_shadow_object_pose_probe.py), and [regression tests](../tests/unit_tests/experiments/test_shadow_object_pose_placement_controls.py). The full Docker suite passed **548 tests, 12 skipped**. The simulator experiment suite passed **92 tests** with both tests and scripts mounted read-only. No production retarget or replay path changed.
