# Visual pressure/contact hints for ViKi — 26 October 2026

The useful experiment is to infer a human contact/load prior from all eight HO-Cap views and ask whether it improves robot retargeting. The user explicitly chose this direction. Full HO-Cap coverage is available locally; occlusion is not a reason to defer the pilot. Predictions should guide contact selection, relative finger importance and release timing. Physical success is evaluated by unforced MuJoCo replay, not by whether a pressure heatmap looks convincing.

## Concrete pilot

[Inference runner](../experiments/hocap_pressure_hint.py) processes subject_1/20231025_170105, original frames0–189, all eight cameras. It uses official calibration and annotated joints only to obtain repeatable hand crops and per-digit image regions; the network itself receives RGB, not joint geometry, simulator state or success labels. Cropping matches upstream's 1.5× square bounding box, image size448, RGB/ImageNet normalization. Published nine pressure classes are decoded with the original midpoint mapping, including the96kPa final bin. The auxiliary seven outputs mean thumb/index/middle/ring/little/palm/weak high-versus-low level; that last output is not a force in newtons.

Preserve per-view maps and probabilities. A fixed fusion rule averages the strongest two views for each finger/frame; it is a heuristic to use complementary cameras, not a newly trained multiview estimator. Projected capsule image regions are approximate, so retain visual overlays and assess false positives. Relative importance is fused mean pressure proxy multiplied by fused predicted finger participation. Pixel values are **not summed into newtons**: that would need calibrated contact area, surface normals and reliable surface assignment. Different human/robot skin and geometry make direct pressure copying inappropriate, but do not prevent using it as an optimization weight.

The bounded comparison should use the same source commands, scene, friction, mass and servos: current best grasp; a geometry-only contact correction; the same correction weighted by the visual hint. Use identical candidate/optimization budgets. Optimize missing high-weight finger contact while preserving thumb/opposition and limiting pose deviations, self-collision and table collisions. Report real positive-force participation per digit, palm-relative object slip/rotation, carry and upright post-release placement. A reduction in pressure/contact loss alone does not establish improvement. Record negative outcomes as well as positive ones.

The pilot is isolated under ignored `data/experiments/hocap-rl/pressure_hint_20261026/`, with upstream code/checkpoint and dependencies; production packages/configuration are unchanged. Runtime: existing experiment image, GPU enabled in a temporary Compose override, PyTorch2.8/CUDA12.8, segmentation-models-pytorch0.3.3, timm0.9.2, pretrainedmodels0.7.4, efficientnet-pytorch0.7.1. Checkpoint load and a448×448 forward pass succeeded. Measured inference results follow; retarget ablations are recorded separately.

## Measured eight-view inference

All **1,520 original RGB frames (8 cameras × 190 frames)** were processed locally. The source archive already contained all eight cameras; the episode's two convenient preview videos were not the full source coverage. No training or simulator-success labels entered inference. [Compact results and checksums](../paper/results/visual_pressure_pilot_2026_10_26/) include complete per-view/per-frame digit statistics and an eight-view overlay at frame90; larger per-pixel maps and original crops remain in the ignored working directory. Checkpoint SHA-256 is `565f4e766dc860454f620c9df867dd3d86e15377718bc137fd33dae083a9174c`.

The published hard-class decoding yields **zero median pressure proxy for every finger during carry42–125**. This prompted one explicit diagnostic rerun preserving the original hard-decoding report: retain the softmax expectation over the same nine published pressure bins, without retraining or changing their thresholds. The expectation is a model output, not calibrated pressure on this bottle.

Each entry is the temporal median after fixed top-two-view fusion. The auxiliary head has some phase information; the soft pressure expectation has weak separation between grasp and free-hand phases. This establishes **weak transfer of this published checkpoint on this clip**, not a failure of force hints in general. The [independent source-hand geometry audit](2026-10-26-source-finger-audit.md) finds ring proximity throughout carry and little-finger proximity in most frames. Thus missing robot ring/little contacts cannot simply be dismissed as absent source participation. Geometry proximity itself does not measure force.

For the retarget ablation, freeze the median of soft pressure expectation × auxiliary participation over carry, then normalize ring/little and use `1 + normalized_share`: weights **1.53487 / 1.46513** versus geometry-only **1 / 1**. This uses learned information as a modest contact-priority hint and makes no conversion to newtons. Both optimization arms receive identical source commands, variables, physical models and budgets. Their measured results are recorded separately rather than selecting a favorable pressure threshold after observing replay success.

## Completed constrained comparison and parent review (29 October)

The initial gap-only proposals collided between retained ring/little middle/distal geometry pairs; all four backtracking scales failed screening. Those outcomes do not establish an optimum: review also found default finite differences too small for float32 command construction. The corrected constrained comparison uses SLSQP, maximum80 iterations, explicit finite-difference step1e−4, the same five residual variables and original bounds, and self/floor constraints at nine fixed frames. Full-trajectory screening remains mandatory. A second control correction equalizes total contact weight: **geometry1.5/1.5 versus visual1.53487/1.46513**, keeping the regularizer unchanged. Earlier failures and interrupted numerical/control-correction runs remain in their original ignored output directories.

Both corrected arms converged after35 iterations. Full-trajectory screening accepted only the predeclared quarter-scale residual for either arm. Both then ran the original190-frame physics and a separate2-second static hold. Ring/little positive-force participation remained **zero** in both; thumb plus two other fingers persisted during99.96% of carry steps. Geometry versus visual static slip was14.35 versus14.40mm, vertical drop18.14 versus18.16mm, relative rotation21.03 versus21.28°. Neither static-hold nor original task/full-scene gates passed. There is **no demonstrated benefit of this visual weighting in this bounded experiment**; this is one checkpoint, clip and residual family, not a rejection of contact/force priors generally.

The parent independently replayed both saved commands using the original replay scene XML, without controller/optimizer helpers. Object positions, rotations and actual robot joint trajectories match the agent outputs **bit for bit**. [Reports, commands, protocol and independent comparisons](../paper/results/visual_pressure_pilot_2026_10_26/) are durable and checksummed. The full repository suite passed559 tests (13 skipped); experiment tests in the simulator image passed104 tests. These tests check implementation contracts, not physical task success.

Following the user's scope question on29 October, these dynamic failures remain recorded as dynamic diagnostics. They do not by themselves invalidate geometric retargeting or the usefulness of human RGB-D/geometry for learning. Conversely, geometry-only success does not establish directly executable robot demonstrations or downstream policy improvement. These are separate claims requiring separate evaluation; no recorded failure is relabeled as success.
