# First simulator imitation-learning attempt — 2026-10-12

## Data and control contract

The source remains the 22 geometrically accepted scratch plans in
`data/experiments/recovered-retarget/`; no original recording, calibration,
object model or canonical plan was changed. MuJoCo replay with the same old
UR10, two-finger Robotiq, provisional rubber-pad/contact settings, 3× command
time and 0.10 rad simulator-only grasp pressure produced **17/22** physically
successful plans at a **50 Hz held-command** control rate. Only those 17 were
saved under `data/experiments/bc-v1/rollouts/`, with a manifest including all
22 decisions. The executed state and command are logged before each 20 ms
physics interval; the next interval uses the same held command. The raw physics
step remains 2 ms. This is a simulator dataset, not robot telemetry.

Each observation has 53 values: six arm joint positions and velocities,
finger position and velocity, then red/green/blue cube XYZ, quaternion and
six free-joint velocities. The action is seven **position targets** (six arm
joints plus finger), not a measured contact force. Training predicts the
target-minus-current-position residual, with train-only normalization. The
network receives no plan timestamp, task phase or future object pose. Cube
poses are privileged MuJoCo state; a real camera policy would require a
separate estimator. All 17 demonstrations remain contact-imperfect: 16 touch
the red support at the tested 50 Hz controller settings.

## BC result

The 17 source episodes were split by entire episode, never by frame:
**12 train / 2 validation / 3 test** (seed 42). The two-layer 128-unit MLP
selected epoch 30 by validation action error, using 14,368 / 2,298 / 3,458
samples. Normalized action MSE was 0.00295 train and 0.00586 validation.
Those are teacher-state prediction errors, **not task success**. Running the
checkpoint as a 50 Hz feedback policy for 40 seconds in MuJoCo gave
**0/12 train, 0/2 validation, 0/3 test** released stable stacks; the blue cube
was never lifted. This is a failed first BC baseline, not evidence that ViKi
demonstrations train a capable manipulation policy. Matching the teacher and
student command rates did not fix the failure. The policy moves the arm but
misses the cube in closed loop; further diagnoses must focus on feedback,
phase ambiguity and compounding pose errors rather than optimizing offline
action MSE alone. Results and checkpoint are in `data/experiments/bc-v1/`.

## No-learning control and layout sensitivity

As a sanity baseline, command sequence from the single source
`2026-10-06_11-01-57` was replayed at the same 50 Hz held-command rate,
unchanged in **all 22** accepted scenes:
**22/22** satisfied the same MuJoCo grasp-and-stack predicate. This is *not*
learning or out-of-layout generalization: the scenes share practically the
same cube positions and simulator assumptions. It also means the earlier
17/22 per-plan result reflects trajectory quality, not an intrinsic need
for 17 different motions at this fixed layout. Across the 17 original
physics-successful scene models, red cube initial XY spans only 11.1 × 13.0 mm
and green only 4.3 × 6.7 mm; these are reconstructed positions, not external
ground truth.

With source commands fixed, moving the red+blue stack and green target
independently by seeded uniform ±20 mm in each XY axis gave **9/25** successes
at the matched 50 Hz command rate. An earlier continuous-command diagnostic
gave 11/25; it is superseded by the matched-rate result.
This small, *in-sample-chosen* template and 25-trial probe is diagnostic only;
it is not a policy generalization benchmark or publication-grade interval.
Both replay settings still inherit provisional contact dynamics and may
brush the red cube. Outputs:
`data/experiments/bc-v1/template_baseline.json` and
`data/experiments/bc-v1/template_perturbation_20mm.json`.

## Decision

Do **not** claim that the current BC policy works, or spend time recording
more repetitions of the same fixed arrangement. The next experiment should
generate object-relative *candidate* motions for varied reachable cube
positions, retarget and physics-filter them, then train/evaluate on source-
disjoint and layout-disjoint splits. Keep the single-trajectory controller
as the strong fixed-layout baseline. Avoid modifying the grasp-position
offset to conceal the failure; no such change was made here. RL from scratch
and demonstration-assisted RL remain later comparisons, after a useful
state-action dataset and task environment exist.

## Reproduce

```bash
docker compose -f docker-compose.experiments.yml run --rm sim experiments/collect_bc.py
docker compose -f docker-compose.experiments.yml run --rm sim experiments/bc.py train
docker compose -f docker-compose.experiments.yml run --rm sim experiments/bc.py evaluate
docker compose -f docker-compose.experiments.yml run --rm sim experiments/template_baseline.py
docker compose -f docker-compose.experiments.yml run --rm sim experiments/perturbation_eval.py --count 25 --offset-mm 20
```
